## HAR 脱敏脚本 Win7 卡死修复
- **问题**：用户在 Win7 拖拽 9.6MB HAR 到 mask_har_pw.cmd，黑框空白卡住不动。
- **根因**：(1) PowerShell 处理大 JSON 极慢（ConvertFrom-Json + 逐字符 Mask-Text + ConvertTo-Json + \uXXXX 还原）；(2) 无任何进度提示，用户无法区分"正在跑"vs"已卡死"。
- **修复**：
  - 两个 cmd 启动器：去掉 `chcp 65001`（Win7 兼容性风险），加 `[*] Starting... please wait` 提示。
  - mask_har.ps1：加 `[1/5]~[5/5]` 分阶段进度输出；文件大小显示（MB）；>5MB 大文件预警；错误时 pause 等待用户看清报错。
  - **性能优化（关键）**：`\uXXXX` 还原从 O(n*m) 的循环 Remove/Insert（不可变字符串反复拷贝）改为 StringBuilder 单遍遍历。对 9.6MB 文件从可能数十分钟降到可接受范围。
  - PS 版仍比 Python 慢，>5MB 时建议用 Python 版（mask_har.cmd）。
- 验证：端到端测试通过，中文可读、脱敏正确、静态资源保留。

## PS 版 JSON 解析失败修复（第二轮）
- **问题**：Win7 上拖 9.6MB HAR 到 mask_har_pw.cmd，`[3/5] Parsing JSON` 报错：`Invalid JSON primitive: 0`（Parameter name: u0030）。
- **根因**：PowerShell 的 ConvertFrom-Json 对 HAR 文件解析失败，可能原因：(1) Chrome 导出的 HAR 带 UTF-8 BOM；(2) 文件中含控制字符（\x00 等）PS 不认。
- **修复**：
  1. 改用 `ReadAllBytes` 读文件 → 检测并剥离 UTF-8 BOM（EF BB BF）→ 再转字符串。
  2. 正则去除控制字符 `[\\x00-\\x08\\x0b\\x0c\\x0e-\\x1f]`（保留 \\t\\n\\r）。
  3. `ConvertFrom-Json` 包 try-catch：失败时显示具体错误原因 + 引导用户用 Python 版（mask_har.cmd）+ pause 等待看清提示。

## PS 版 ConvertFromUtf32 代理对报错修复（第三轮）
- **问题**：Win7 上 `[5/5] Writing output` 阶段报错：`A valid UTF32 value should not include surrogate values (0xD800-0xDFFF)`。输出文件已生成（非终止性错误）。
- **根因**：`\uXXXX` 还原循环中，HAR 含 UTF-16 代理对码点（0xD800-0xDFFF），不是合法 Unicode 码点，`ConvertFromUtf32()` 拒绝。
- **修复**：还原前检查码点范围——只处理合法区（0-0xD7FF, 0xE000-0x10FFFF）；代理区和超范围保留原始 `\uXXXX` 不变；加 try-catch 兜底；显示跳过数量。

## PS 版输出非法 JSON 修复（第四轮，最终）
- **问题**：PS 版处理完后导入软件报错 `Invalid \escape: line 44730`——输出文件不是合法 JSON。
- **根因**：`\uXXXX` 还原逻辑（即使加了代理对检查）仍然破坏 JSON 结构。ConvertTo-Json 对 emoji 等输出代理对（\uD83D\uDE00），逐个码点还原会拆散代理对。
- **最终修复**：**彻底去掉 `\uXXXX` 还原步骤**。直接写 ConvertTo-Json 原始输出。\uXXXX 是合法 JSON，任何解析器都能读。中文可读性用 Python 版（mask_har.cmd）满足。
