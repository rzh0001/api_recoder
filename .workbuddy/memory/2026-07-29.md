## 项目：api_recoder（API 录制客户端）初始化

做了什么：从零搭建了一个用 DrissionPage 拉起浏览器、监控所有 API/资源请求、按域名组织成树形结构实时展示的桌面客户端。

技术栈与关键决策：
- 后端：Python + DrissionPage 4.1.1.4（网络监听）+ Flask 3 + flask-sock（WebSocket 实时推流）。
- 前端：pywebview 原生窗口内嵌网页 UI（含 /static/index.html, app.js, styles.css）。
- 内核：默认「自带 Chromium」（首次启动从 Chrome-for-Testing 下载到 runtime/chromium/，见 browser_manager._download_chromium），可一键切「本机浏览器」（注册表+常见路径探测，local 模式）。
- 监控：page.listen.start(method=True, res_type=True) 捕获所有 HTTP 方法+所有资源类型；监听是「按 tab」的，故 BrowserManager 对所有 tab 挂监听并轮询新开 tab（_watch_tabs）。
- 数据：DataPacket → record（tldextract 提取主域名作一级节点，host 作二级，请求作三级）。body 实时推送截断到 200KB、存储截断到 2MB；导出 HAR（HAR 1.2）与 JSON。
- 默认端口 6789（env API_RECORDER_PORT 可改；本沙箱 6789 被 WSAEACCES 占用，测试用 18680）。

验证情况：
- tests/smoke.py 通过（mock DataPacket 验证解析/统计/HAR/截断）。
- 起 Flask 服务并 curl：/、/static/*、/api/status、/api/export、/api/clear 均 200；/ws 连上即收 snapshot；/api/start 在无浏览器时优雅返回 500 且不崩服务。
- 真实浏览器拉起+抓包未在本环境验证（无显示/无 Chrome），需用户在 Windows 本机运行。

运行方式（用户侧）：cd 项目根；`python -m venv venv && venv\Scripts\pip install -r requirements.txt && venv\Scripts\python main.py`。

## 修复：main.py 启动报 WSAEACCES(10013) 本地服务起不来

现象：用户在本机 `python main.py` 报「以一种访问权限不允许的方式做了一个访问套接字的尝试」，随后「本地服务未能在预期时间内启动」，退出码 0（Flask 在守护线程里 bind 失败，main 的 wait_for_port 超时后 return 退出）。

根因：默认端口 6789 落进了 Windows 的 TCP 保留/排除区间（Hyper-V/WSL2 等会自动保留一段端口），`bind()` 被系统拒绝 10013，**即使没有进程占用也会失败**。实测：6789/6790/8080 都报 10013，而 8000/5000/9000/5001/7777/8888 可正常 bind。

修复（三处）：
- config.py：PORT 改为优先读 env `API_RECORDER_PORT`，未设置则 `None`；新增 `PORT_CANDIDATES = [6789, 6790, 8080, 8888, 8000, 5000, 9000, 5001, 7777, 0]`。
- server.py：新增 `resolve_port(preferred)`，按候选顺序 bind 测试（成功即关并返回），末尾 0 交给系统分配；`__main__` 改用 resolve_port。
- main.py：`main()` 先 `resolve_port(PORT)` 拿到实际端口，传给 run_flask / wait_for_port / 窗口 URL，并打印启动地址。

验证：起服务并 GET /api/status 返回 200（实际选到 8888）。已清理临时文件。
注意：仍可用 `set API_RECORDER_PORT=xxxx` 强制指定端口（若该端口也在保留区间仍会失败，会回退到候选）。

## 修复：点「开始录制」不弹浏览器

现象：点开始录制没反应/不弹浏览器。

根因：默认 builtin 模式优先下载自带 Chromium。runtime/chromium 里只有 100MB 的 chrome-win64.zip 半截包（无 chrome.exe，下载被截断），每次点都重下 150MB 的包；而 googlechromelabs.github.io 在国内很慢/易超时，下载卡住时 /api/start 一直不返回，UI 只把按钮置灰、无任何提示 → 看起来「没反应」。本机其实装了 Edge（C:\Program Files (x86)\Microsoft\Edge\Application\MsEdge.exe），`_detect_local_browser()` 能探测到。

修复（browser_manager.launch 的 builtin 分支）：自带内核不存在时，**先**用本机已装 Chrome/Edge（免下载、秒开），只有本机也没有浏览器时才尝试下载内置 Chromium。这样默认模式在有浏览器的机器上不再卡下载。

补充：UI 的「内核」下拉框本就有「本机浏览器」选项，用户也可直接选它。已删除截断的 chrome-win64.zip 残包。

验证：py_compile 通过；`_detect_local_browser()` 实测返回 Edge 路径。实际 GUI 拉起未在本环境验证（无显示）。

## 新增：导出脱敏（字符级遮盖）

用户要求导出时对文本做脱敏：中文→测、数字→1、英文字母→a，其余符号原样保留（保结构）。例：`茅子今年25岁,email是maozi@example.com` → `测测测测11测,aaaaa测aaaaa@aaaaaaa.aaa`。

实现：
- capture_store.py：新增模块级 `mask_text(text)`（按码点判断 CJK 基本区/扩展A/B→测；全角/半角数字→1；全角/半角字母→a；其他保留）。新增 `_mask_record(rec)` 对 url、request.post_data、request.headers(值)、response.body、response.headers(值)、fail_info(若字符串) 做遮盖（deepcopy，不改原记录）。`export_json(desensitize=)`/`export_har(desensitize=)` 增加参数，True 时导出脱敏副本；meta 加 desensitized 标记。数值字段（status/size/duration_ms/timing）不动。
- server.py：`/api/export` 读 `desensitize` 查询参数（1/true/yes/on）。
- 前端：工具栏加「脱敏导出」复选框；app.js exportUrl() 勾选时追加 `&desensitize=1`。

坑：_mask_record 先写成模块级却用 self._mask_record 调用，已改为模块函数调用 `_mask_record(r)`。

验证：样本导出脱敏后 url=`aaaaa://aaa.aaaa.aaa/aaaaa?aaaa=测测&aaaa=11111111111`、post_data 中文/数字/英文均按规则替换、Authorization=`aaaaaa aaa111aaa`、status 仍为 200；JSON+HAR 均生效。node --check app.js 通过；server 包导入 OK。

## 修复：树形列表出现重复节点（registered_domain == host 时）

现象：用户截图显示 `localhost:4000` 出现两次——一次作为一级域名节点，一次作为二级 host 节点。
根因：`localhost:4000` / IP 地址等非标准域名，tldextract 提取不出有效注册域名，fallback 到 fqdn（即 host 本身），导致 registered_domain == host，渲染时两层都显示相同名字。
修复（app.js render 函数）：遍历 hostArr 时判断 `if (host === rd)` 则跳过中间 host 层包装，直接把请求行挂到域名节点下。对正常域名（如 api.example.com vs example.com）无影响，host 层照常展示。
坑：编辑时 `</span>` 误打成 `</span}`，已修正；node --check 通过。

## 脱敏规则可配置

用户要求脱敏规则可配置（原来硬编码 测/1/a）。

实现：

验证：mask_text 默认=原行为；自定义 测/1/a→*,9,x 生效；仅中文（留空其他）=数字英文保留；全角 ＡＢ１２测→aa11测；填空串=删除该类。node --check 通过；py_compile 通过。

## 修复：脱敏范围收窄到仅请求体+响应体

用户反馈：当前脱敏无差别覆盖 URL/header/body，导致 API 端点、JS/CSS 路径、host 全变成 aaaaa/1111，导出文件完全无法用于分析（截图可见 localhost:4000→aaaaaaaaaaa:1111、所有 chunk 路径变 /aaaaa/...）。

根因：_mask_record 对 url / request.headers / response.headers 全部做了 mask_text。

修复：_mask_record 改为**只脱敏 request.post_data 和 response.body**（业务数据内容）；URL/path/query/host/headers/status/method/resource_type/timing 等全部原样保留。理由：
- URL/端点保留 → 能识别调了什么接口
- 静态资源路径保留 → 能区分 JS/CSS/图片
- headers 保留 → Content-Type/Accept 等结构头必须保留；Authorization/Cookie 等 header 的 key 本身已暴露"有此字段"，遮盖 value 无实际安全收益
- 只有 body 里的业务数据需要脱敏（姓名/手机号/余额等）

验证：同一样本导出后 url/Authorization/Content-Type/host 原样，post_data 和 response body 按规则脱敏，status 不变。

## 修复：静态资源不脱敏，仅 API(XHR/FETCH)的 body 脱敏

用户反馈：JS/CSS 静态文件的响应体也被脱敏（截图可见 JS chunk 内容全变成 aaaaa），既无隐私风险又破坏文件可用性。要求：只对 API 结果数据脱敏，静态文件不动。

修复：_mask_record 加 `resource_type` 判断——仅当 rt 为 XHR 或 FETCH 时才对 post_data 和 response.body 做 mask_text；SCRIPT/STYLESHEET/IMAGE/FONT/MEDIA/DOCUMENT/OTHER 等全部原样保留。

验证：同一样本 XHR body 脱敏（{"aaaa":"测测",...}），SCRIPT body 原样（const name="茅子";...）。py_compile 通过。
